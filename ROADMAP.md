# Планирование HydroLauncher

Короткий план развития после 0.2.7. Этапы идут по возрастанию сложности и не
ломают друг друга: каждый заканчивается проверками из CI и отдельным коммитом.

## Сделано

### 1. Очередь задач установки
- До двух операций одновременно, сериализация по одной сборке.
- Пауза, отмена, повтор и история задач в `jobs.json`, которая переживает
  перезапуск лаунчера.

### 2. Обновления, целостность и Java
- Каналы `stable`, `beta` и `alpha` с предпросмотром обновления.
- Проверка SHA-1 установленных файлов и защита вручную изменённых модов.
- Рекомендуемый лимит памяти по объёму ОЗУ и выбор Java из найденных рантаймов.

### 3. Хранилище и импорт перетаскиванием
- Отчёт по категориям и сборкам, безопасная очистка только кэша и логов.
- Распознавание перетащенных объектов по содержимому: модпак, архив сборки,
  Prism/MultiMC, мир, ресурспак и мод; для контента выбирается целевая сборка.

### 4. Headless-бинарник `hydro-cli`
- Те же папка данных и сервисы, что у приложения, но без окна.
- Команды `instances`, `storage`, `cleanup`, `inspect`, `import`, `export`,
  флаги `--json` и `--data-dir`.

## В работе

## Правила этапа

1. Никаких хардкодных URL, путей и личных данных: только
   `src-tauri/src/config/endpoints.rs` и `src-tauri/src/storage/paths.rs`.
2. Интерфейс остаётся в стиле «жидкое стекло», без неона и лишних рамок.
3. Перед коммитом: `npx tsc -b`, `npm run build`, `npx vitest run`,
   `cargo fmt --check`, `cargo check --all-targets`, `cargo test`.
